# 回关检查 · 本地文件夹 / Chrome 扩展版 v2.3.0

**下载 X 存档 ZIP → 放进项目的 `archives` 文件夹 → 双击「启动工具.command」→ 自动显示名单。** 无需解压、填写用户名或选择单个文件，不访问 X。也保留 Chrome 扩展的离线手动导入与可选在线扫描。

## 扩展入口（v2.3.0）

更新后先到 `chrome://extensions` 重新加载本项目 `extension` 文件夹中的扩展，确认版本 **2.3.0**；关闭旧的手动导入页，再点击扩展图标。新增的 `127.0.0.1` 权限只用于检测本机服务，不读取其他网站。

- 已双击「启动工具.command」启动服务：扩展直接在新标签页打开项目存档名单，默认选最新，也可手动切换。
- 服务未启动：扩展显示启动指引；双击启动文件后，再点击扩展或“打开项目存档名单”。此页面也保留“手动导入 / 在线扫描”入口。
- 扩展无法自行启动系统进程或直接读取任意磁盘文件，因此固定目录读取需要本地服务运行。默认地址固定为 `http://127.0.0.1:59931/`，重复启动会复用已运行的同一工具，不新建浏览器配置、不访问 X。

## 项目文件夹模式（推荐）

1. 在 X 的“设置和隐私 → 你的账号 → 下载你的数据存档”申请并下载官方存档。
2. 把下载完成的 ZIP 直接放入本项目的 **archives** 文件夹。也可以放入完整解压后的存档文件夹，或将 `following.js` / `follower.js` 及其全部分片放入 `archives`。
3. 双击 **启动工具.command**。它会打开存档文件夹和本地名单页面，自动读取并比较；页面已打开时，放入文件后点击“刷新文件夹”。
4. 多份存档在下拉框中分别选择；每次打开页面或刷新文件夹自动选择最近修改的一份，也可用下拉框手动切换旧存档。支持搜索、主页链接、CSV 导出。

此模式需要 Node.js 20+；直接读取 ZIP 另需 Python 3（仅使用标准库，无需安装 Python 包）。也可运行 `npm start`，无需先安装 npm 依赖。服务只监听 `127.0.0.1`，仅提供本地页面与比较接口。

ZIP 不会整体解压：只读取文件目录及精确匹配的关注、粉丝名单；不读取私信、媒体或其他账号资料的内容。解压目录支持 `archives/data` 或 `archives/存档文件夹/data`。合计名单上限 100 MB，不接受符号链接或加密名单。同一个 ZIP 内出现多组名单会拒绝比较，避免混用。`archives` 内的个人数据已被 Git 忽略，不会提交到 GitHub。结果仅反映存档生成时的关系。

此入口不依赖扩展，也不自动访问 X；点击账号主页才会打开 X。关闭启动终端可停止服务。

## 扩展离线导入模式

1. 在 X 的“设置和隐私 → 你的账号 → 下载你的数据存档”申请并下载官方存档。
2. 解压后，从 `data` 文件夹选择 `following.js`（你关注的人）与 `follower.js`（关注你的人），分别导入扩展页面。
3. 若有多个分片，每份名单都需选择完整的 `part0`、`part1` 等文件。点击“本地比较名单”，可搜索账号 ID / 用户名、查看主页、导出包含 ID 的 CSV。

导入过程中不访问 X、不提取登录态、不上传或持久保存文件。文件作为 JSON 文本解析，不执行其中的 JavaScript。支持标准 `window.YTD.following.part0 = [...]` / `follower` 存档以及相同记录结构的纯 JSON 数组。两份名单合计上限 100 MB，单份名单最多 1,000,000 条；按字符串 ID 去重，保留大整数精度。

结果只反映存档生成时的状态。工具不能核实两个名单是否来自同一次导出，也不能发现末尾未选择的分片，请选择同一次存档的全部名单文件。缺少用户名时显示账号 ID 并提供 ID 主页链接；点击链接才会打开 X。扩展入口只接收单独的名单文件；要直接使用 ZIP，请使用上面的项目文件夹模式。

## 更新现有扩展

在 `chrome://extensions` 点击扩展的重新加载按钮，然后关闭旧检查页、重新点击扩展图标。确认版本为 2.3.0。

## 首次安装

1. 在你平时使用且已经登录 X 的 Chrome 中，地址栏输入 `chrome://extensions`。
2. 开启右上角“开发者模式”，点击“加载已解压的扩展程序”。
3. 选择本项目里的 **extension** 文件夹；该文件夹内直接包含 `manifest.json`。
4. 在任意网页打开 Chrome 工具栏“扩展程序”菜单，点击“回关检查 · X 本地工具”，可将它固定到工具栏。
5. 扩展会在同一个 Chrome 窗口的**新标签页**打开项目存档名单；本地服务未运行时显示启动指引。

首次连接可能刷新原 X 标签页以加载扩展；登录状态会保留。Chrome 的网站访问权限需允许扩展在 x.com 运行。安装步骤由用户在 Chrome 完成，本工具不会静默安装扩展或修改浏览器配置。

扩展内手动导入和在线扫描不需要运行 Node.js 或本地服务器；默认项目文件夹入口需要本地服务。`启动工具.command` / `npm start` 现在打开项目文件夹模式，页面另有“扩展安装指引”链接；扩展扫描不经过本地服务。

## 在线扫描行为（可选）

在线模式会自动访问及滚动 X 网页，存在平台限流或账号限制风险。选择“在线扫描”，点击“连接 / 重新识别”，再点击扫描。仅切换模式不会连接或刷新 X。

- 从 X 的“个人资料”导航和账户切换按钮识别当前登录账号，不把正在浏览的其他用户当成自己。
- 在原 X 标签页打开你自己的资料、关注、粉丝页面并自动滚动；在扩展检查页显示进度。
- 读取这些页面自然收到的公开名单响应，按用户 ID 去重、对比。
- 两份名单人数须与账号资料一致，末尾重新读取资料复核；不完整、限流、人数变化或账户切换都不生成未回关结论。
- 完成或取消后尽量恢复原 X 页面（仅当标签页仍停留在工具导航的页面）。始终不关闭 X 标签页、不退出登录。
- 结果支持搜索、主页跳转、CSV 导出；不提供自动取关。
- 如果切换了 X 账号，点击“重新识别”，无需手动输入用户名。

请保持 X 标签页与检查页面都打开，扫描期间不要在原 X 标签页手动导航或切换账号。关闭检查页面会停止后续读取；X 可能停留在当前扫描页面，登录仍然保留。结果仅在检查页内存中，刷新或关闭后清空。

## 权限与数据

请求 `https://x.com/*` 网站访问权限和 `http://127.0.0.1/*` 本机服务访问权限。没有 cookies、debugger、所有网站、浏览历史或下载管理权限。不读取现有 Chrome 配置、密码、系统钥匙串、Cookie 或请求头，不提取认证令牌。会话由 Chrome 和 X 正常处理。

MAIN world 脚本只监听 `UserByScreenName`、`Following`、`Followers` 网页响应，将 ID、用户名、名称和人数等白名单字段传给扩展内容脚本。不会将原始响应或认证信息发给本地服务器。没有第三方分析和上传服务。网页响应属于网页提供的数据；页面本身能干扰 MAIN world 脚本。

## 已知限制

X 可以限流、截断名单、隐藏停用账号或更改响应格式；这些情况下工具会拒绝输出确定结果。单份名单上限为 100,000 人。读取前后人数相同也不能保证扫描期间关系完全没变，手动取关前应打开主页核对。

这不是 X 官方 OAuth 应用，不调用付费开发者 API，也不绕过验证或访问控制。真实 X 扫描需要在你的已登录 Chrome 内验证；本地集成验收使用仿真 X 页面，不代表平台一定允许完整读取。

## 开发验收

需要 Node.js 20+ 与 Playwright 的 Chromium（支持扩展加载）。运行 `npm install`、`npx playwright install chromium` 后运行 `npm test`。测试全部使用临时浏览器配置和仿真网页，不读取现有 Chrome 用户目录或真实凭据。不创建或运行单元测试。

Manifest、账号识别、页面响应桥、扫描与结果展示分别位于 `extension/manifest.json`、`content.js`、`page-bridge.js`、`scan.mjs` 和 `dashboard.js`。参考 [Chrome 内容脚本说明](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

## v2.0.1 兼容修复

支持新版 `user_result_by_screen_name.result` 资料根节点。精简资料缺少旧版人数时，仅在自己的资料页面读取精确数字（包括数字标题）；不将 K、万等缩写换算成人数，不将缺失值当成 0。更新本地文件后，请到 `chrome://extensions` 点扩展的重新加载，再关闭旧检查页、刷新 X 并重新点击扩展。
