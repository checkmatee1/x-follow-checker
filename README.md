# 回关检查 · 本地存档工具 v3.0.0

**下载 X 存档 ZIP → 放进 `archives` → 双击「启动工具.command」→ 查看未回关名单。**

## 如何下载 ZIP

1. 在已登录 X 的“更多 → 设置和隐私 → 你的账号 → 下载你的数据存档”中申请存档，按 X 提示完成身份验证。
2. 等待邮件或站内通知，准备存档可能需要几天。
3. 在已登录 X 的浏览器里下载 ZIP。[X 官方下载说明](https://help.x.com/en/managing-your-account/how-to-download-your-x-archive)。
4. 将下载完成的 ZIP 放到本项目的 **archives** 文件夹，无需解压。也可以在 Chrome 的“另存为”窗口直接选择此文件夹。

## 启动与使用

需要 **Node.js 20+**；直接读取 ZIP 另需 **Python 3**，仅使用标准库，无需安装 Python 包。日常使用不需要运行 npm install。

双击项目中的 **启动工具.command**，会启动本机服务，并打开存档文件夹及名单页面。也可在项目目录运行 `npm start`，地址固定为 `http://127.0.0.1:59931/`。保持启动终端打开；按 Control+C 或关闭终端可停止服务。重复启动会复用正在运行的同一工具。

打开页面或点击“刷新文件夹”会自动选择最近修改的一份存档，也可用下拉框手动切换其他存档。支持账号 ID / 用户名 / 名称 / 简介搜索、分页、主页链接和 CSV 导出。页面已打开时，放入文件后点击刷新即可。

也支持解压后的 `archives/data`、`archives/存档文件夹/data`，或直接将 `following.js` / `follower.js` 及其全部分片放入 `archives`。多份存档分开处理，不会合并。

## 文件与隐私

只读取 ZIP 文件目录及精确匹配的关注、粉丝名单条目，不整体解压，不读取私信、媒体或其他账号资料的内容。不执行存档中的 JavaScript，只解析其中的 JSON 文本。

比较过程不访问 X、不读取登录态、不上传存档。打开或刷新页面会读取本地资料缓存；仅点击资料查询按钮时，向 X 的公开时间线组件发送待查询的数字账号 ID，并下载对应公开头像，不发送名单文件、不使用浏览器登录态或 API Key。点击外链会打开对应网站。服务仅监听 `127.0.0.1`，名单接口拒绝跨源访问；存档文件不作为网页文件提供。`archives` 内的个人数据已被 Git 忽略，不会提交到 GitHub。

## 限制

结果仅反映存档生成时的关系，不是当前实时状态。请使用同一次完整存档；工具无法判断末尾是否遗漏分片。缺少用户名时显示账号 ID 并提供 ID 主页链接；可点击“补全或更新资料”联网补全，手动操作前仍应打开主页核对。

名单按字符串 ID 去重，保留大整数精度；两份名单合计上限 100 MB，单份名单最多 1,000,000 条。缺失或重复分片、损坏 JSON、无效 ID、加密名单、符号链接及一个 ZIP 内包含多组名单时拒绝生成结论。

## 开发验收

运行 `npm install`、`npx playwright install chromium` 后运行 `npm test`。Playwright 仅用于开发验收，使用临时浏览器与合成存档，不读取现有浏览器配置或真实账号数据。不创建或运行单元测试；实现结束后集中执行完整集成验收。

运行代码位于 `src/server.mjs`、`src/archive-folder.mjs`、`src/archive.mjs`、`scripts/read-archive-zip.py` 和 `public/`。

## 无需 Key 的资料查询与缓存

资料查询入口位于页面上方的“项目存档文件夹”卡片内。点击 **补全或更新资料**，只补查当前未回关名单中缺失、缓存过期或仅有旧版用户名缓存的账号，每批 3 个，逐个保存。结果表显示头像、简介、粉丝数和关注数，简介也支持搜索，CSV 包含简介和两项数量。未知数量显示“—”，实际数量为 0 时显示“0”。

账号资料和头像图片本身保存在 `archives/.profile-cache/user-profiles.json`，有效期统一为 **7 天**，跨刷新、重启、存档复用。7 天内普通补查不会重复联网；过期后仍显示上次资料，点击补查时再更新。旧用户名缓存继续显示，首次补查时获取新增字段。点击 **强制更新全部资料** 可在 7 天内提前刷新，更新失败保留旧数据及原更新时间，不延长其有效期。未取得资料的账号也暂缓 7 天再补查；强制更新可提前重试。连接失败或限流时暂停联网 5 分钟。

头像只在资料查询时从 `pbs.twimg.com` 下载，作为图片数据缓存，翻页和刷新不会访问远程图片。头像不可用时显示姓名占位符，不影响其他资料显示。单张头像限制 128 KB，资料缓存总量限制 20 MB；达到容量时优先释放最早缓存的头像图片，保留文字资料和数量，避免阻断后续查询。头像或其他字段更新失败时保留原有字段；仅文字资料本身超限时才报告错误并保留原缓存。

公开数据来自 `https://syndication.twitter.com/srv/timeline-profile/user-id/<ID>`。这是 X 的公开网页组件，并非保证可用的正式用户查询 API；私密、停用、无公开时间线或受限账号可能无法获取。字段缺失时显示“—”，页面格式变化、网络限制或限流时会明确提示，已缓存的资料仍可用。资料可能存在延迟，与存档中的历史关系并非同一时间点。

需要系统 `curl`（macOS 自带），沿用进程代理环境变量，不读取 `.curlrc`、浏览器配置或凭据文件。查询期间可点击停止，当前小批结束后停止；断网或后续失败不影响之前已保存的记录。缓存继承 `archives` 的 Git 忽略规则，不会被静态文件服务提供。移走缓存文件即可清空；损坏缓存会报告错误并保留原文件。

更新代码后需重启本地服务；页面若连接旧版后台，会明确提示重启，而不会静默忽略查询。


### 独立临时 mihomo

双击启动工具时，会使用本机 Homebrew 的 `/opt/homebrew/bin/mihomo`，从 `/opt/homebrew/etc/mihomo/config.yaml` 的内联节点和本地提供者缓存创建独立临时实例。需要 Python 3 与 PyYAML。只读取本地节点快照，不更新订阅，也不复制配置进项目。

实例使用随机的本机端口及独立控制器，只代理资料和头像请求。不改系统代理、常驻 mihomo 的节点、TUN、PF 或缓存。主进程退出时监督进程关闭核心并删除临时配置；临时配置与节点快照仅保存在权限受限的系统临时目录，核心日志不输出。

每次资料查询至少间隔 2 秒。HTTP 429 后先等待 15 秒，再换一个候选节点重试；30 分钟内最多自动换两次，失败后沿用资料缓存的五分钟暂停。网络错误不会触发换节点。不同节点可能仍共用出口 IP，切换不保证解除限流。代理退出或不可用时停止联网查询，不自动直连；离线比较和七天资料缓存仍可使用。

启动时会在终端显示临时端口和节点数量，不显示节点认证或订阅。已有旧版服务需先关闭其启动终端再重新双击启动；不要关闭系统常驻 mihomo。临时实例只随工具启动，不会因打开网页或刷新而重复创建。
